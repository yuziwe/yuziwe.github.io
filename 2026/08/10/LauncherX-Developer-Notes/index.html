LauncherX Developer Notes
2026-10-28 13:54:51

Overview

LauncherX 是模仿Windows上的utools和Linux的rofi风格的程序启动器，目前仅支持Windows版本。

utools不开源，rofi开源但不支持Windows，一根筋两头堵

为什么不找找其他开源的程序启动器呢？

emmmm，都不太好用，我还是喜欢亲力亲为，顺便学习下Everything的底层索引机制。

编写此文目的是记录一次完整的QT+Windows开发路径。

2026-09-01 Edited: FlowLauncher开源也好用~

Tech Stack

  • QT6
  • Windows Kit
  • MSVC
  • CMake
  • Ninja
  • SQLite
  • Catch
  • Spdlog

Environment setup

我刚组装的电脑，环境基本为0。

Win Kit

既然是在Windows上做开发，还是和C++桌面应用相关的项目，Windows Kit是绝对绕不过去的。

在微软官方网站上下载好安装文件后，只要选中并安装MSVC compile chain和Windows10/11 Kit即可，其他都不是必须。

Qt kit

这边建议去镜像站找找压缩后的Portable版压缩包，Qt官网下载速度感人。

解压之后，必须把bin目录加入环境变量，否则后续编译/运行都会报错。

CMake & Ninja

这些安装就很简单了，一直下一步就行了。

SQLite

这里选用SQLite作为数据库源，一方面是其最轻量，另一方面则是其本身也提供了全文检索的机制，正好利用学习一下。

Catch & Spdlog

spdlog是我用过集成简单，功能丰富的日志库，此处使用Git submodule的方式引用编译。

Catch是spdlog用的单元测试框架，我也引用学习下。

Project setup

用C/CPP来开发项目，依赖管理是首先要解决的问题，不像其他编程语言，例如Golang，Rust等，出生就带。

C/CPP也不是没有，只不过就像RISC-V架构一样，生态并未统一，各打各的。

那么我就要拿出传统的CMake来管理依赖和编译规则了。

Architecture design

这里采用了简单的三层结构，各司其职。

  • App：负责处理用户输入，界面更新
  • Service：负责实际业务处理，在这里对应的是Full text query和索引构建/更新
  • Repository：负责数据存储，主要和SQLite打交道，无非是一些增删改查

Core machinism design

一共有两大问题需要解决：

  1. 初始索引如何构建；
  2. 增量更新如何做；

对于第一个问题，最简单的方法就是把目标目录扫描一遍，筛选出我们需要关注的即可。

对于第二个问题，有两个场景需要关注。其一，程序运行时的增量更新，这一步我们可以通过Windows API提供的ReadDirectoryChange
配合以自定义的Event loop实现；其二，程序二次运行时的增量更新，这一步依然可以通过全盘扫描的方式实现，之后与现有索引作Diff操作
多的记录就新增，少的记录就删除，同样的记录则更新，这样的实现操作最简单，核心就是把Diff算法写好就行，然而这样的实现涉及到的IO操作
有点多，更理想的一种实现方法则是借助Windows USN（Unique Sequence Number）的帮助筛选出真正需要更新的那一部分，然后统一落盘即可。

Windows USN basic usage

USN，是Windows提供的一种记录磁盘文件变化的机制，每种操作对应一个USN，类似于数据库的binlog，可用于数据恢复。

The USN Journal (Update Sequence Number Journal), or Change Journal,[1] is a feature of the Windows NT file system (NTFS) which maintains a record of changes made to the volume. It is not to be confused with the journal used for the NTFS file system journaling.

对于[Core machinism design](#Core machinism design)中提到的第二个问题中的第二个场景中的第二种方法，我们需要知道从上一次运行到本次运行阶段的USN端点以便于区间遍历，因此首先需要获取当前USN的状态，这里可以通过FSCTL_QUERY_USN_JOURNAL实现。

在枚举USN区间时用到的FSCTL_READ_USN_JOURNAL控制Flag，传入的控制结构体需要指定版本号及UsnJournalID，否则会操作失败。

ReadDirectoryChange usage

这个API倒没啥说的，只不过有一点需要注意，即变更事件触发后需要重置事件并重新调用ReadDirectoryChange注册。
