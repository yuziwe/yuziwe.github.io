Overview

Hmmmm，物理设备模拟还是有点太野了，VirtualBox好像要GUI环境，在Linux无 GUI 环境下最好的模拟工具还得是QEMU。

因此，我就浅浅狗尾续貂，加上这一模拟方法，并伺机添加额外功能。

Prerequsites

因为是面向 UEFI 环境编程，因此肯定少不了相关的依赖库和头文件。

我本地是 Debian 环境，因此可以通过以下包管理器进行安装。

后续需要创建一些 DOS-like 分区，因此需要安装对应的 DOS 工具链。

Things should bear in mind

  1. UEFI 支持的 filesystem 类型只有 FAT 类型

  2. 就像 Linux 上运行的 ELF 格式的程序一样，在 UEFI 环境下执行的程序也有对应的格式，即 PE32+。

  3. PE32+ 格式无法通过 ld 创建，需要使用 objcopy 手动拼接 sections。

Hello World

我们通过创建类似 main 的函数接口实现入口点的实现，可以看到 efi 库的存在类似与 libc，都提供了一层封装。

保存为 .c 文件后，就可以利用 gcc 编译出 object file 用于后续链接生成动态库。

  • -fno-stack-protector -mno-red-zone: 处理栈溢出的 runtime 并不存在于 UEFI 环境，因此需要关掉栈保护。对于 red zone 的禁用，是为了防止 CPU 等中断事件处理时压栈破环当前栈的数据。

  • -fpic: 由于后续需要生成动态库，因此这里启用位置无关选项，避免绝对地址加载无效。

  • -fshort-wchar: 因为 Print 仅接受 UTF16 的参数，gcc 默认将 L"xxx" 视为 UTF32 处理，因此需要转换。

编译成功之后就可以链接产生动态库了。

NOTE: -lefi -lgnuefi 不能放在 test.o 前面。

成功生成动态库后，为了生成最终的 PE32+ 格式的程序，我们需要祭出 objcopy 手动拼接。

NOTE: 作者在其仓库实现的并非这个 tiny project，而是一个 UEFI shell，因此少了 .rodata 段的内容，我们的 Hello world 就存储在这个段中，因此不能省略。

最终的 test.efi 就是我们最终要放进 UEFI 环境中执行的程序咯。
